## F-b · Document model v2 and registries
- [ ] FB-1 — Scene format version bumped (v2) with an explicit **migration chain** (`src/model/migrations.ts`): v1 documents load and upgrade losslessly; `sanitizeDocument` is the single entry; unit tests for v1→v2, unknown future versions (rejected with a clear message), and garbage input.
- [ ] FB-2 — **Shape registry** (`src/model/shapeRegistry.ts` + `src/model/shapes/*.ts`): each shape (box, sphere, cylinder, capsule, cone, wedge, prism, icosahedron) is one `ShapeDef` providing: id, label, icon, category, default size, size normalisation, parameter schema (declarative, drives the inspector), volume, bounding radius, half-height, convex points (if any), Rapier collider factory (`makeCollider(RAPIER, spec) → ColliderDesc | ColliderDesc[]` for compounds), three.js geometry factory. Existing code paths (`shapes.ts`, `world` collider creation, `bodyViews`, palette, inspector) are driven by the registry. Adding a new shape = one new file + one registration line. `ShapeType` becomes `string` (registered id) with validation on load (unknown shape → clear fallback + warning).
- [ ] FB-3 — **Compound-capable bodies**: `BodyEntity.parts?: ColliderPart[]` (each part: shape spec, local position/rotation, optional material override, sensor flag), plus `BodyEntity.meshId?` (reference into `doc.assets`). World builds one Rapier body with N colliders; mass properties, COM, inertia, volume, energy, picking and rendering all work for compounds. Unit tests (compound mass/COM, falling compound rotates correctly, parts with different friction).
- [ ] FB-4 — **Asset store**: `doc.assets: Record<id, Asset>` for meshes (positions/indices/normals/uvs as base64 typed arrays, optional materials), textures (data URLs), heightmaps, audio samples. Serialization compresses/dedupes; share links and export include assets; sanitising enforces size caps. API: `assets.add/get/remove`, ref-counted garbage collection on save.
- [ ] FB-5 — **Extra per-body physics fields** (with inspector wiring left to later packages but present in the model, sanitise, serialize, world build/update): `collision: {group:number(0..15), mask:number(16-bit)}` (collision groups/filters), `drag: {linear2:number, angular2:number}` (quadratic drag), `massOverride?: number`, `comOverride?: Vec3`, `inertiaScale`, `sleepThreshold`, `tags: string[]`, `layer: string`, `parent?: string` (group parent). Backwards compatible defaults.
- [ ] FB-6 — **New entity kinds** in the store, serializer, undo, outliner (basic listing + icons) and sim protocol hooks: `group` (folder with transform, `children` by parent link), `light` (point/spot/directional/area; no behaviour yet beyond storage + a basic rendering hook), `path` (spline/waypoint list: points, closed, tension), `zone` is **not** a new kind (zones are bodies with components). Each kind has factory, sanitiser, clone, store tests.
- [ ] FB-7 — **Component system**: `BodyEntity.components: ComponentSpec[]` (`{id, type, enabled, params}`) and `JointEntity.components`. `src/model/componentRegistry.ts`: `ComponentDef` (type, label, icon, category, appliesTo: body|joint|any, defaults, sanitise, declarative field schema for the inspector incl. number/bool/enum/vec3/color/key/entity-ref/path-ref/curve). Physics-side `src/physics/components/registry.ts`: `ComponentRuntime` (`create(ctx)`, `prestep(dt, ctx)`, `poststep(dt, ctx)`, `onEvent`, `dispose`) with a `ctx` giving safe access to the world (bodies by id, apply force/impulse, raycast, set velocity, query contacts, emit events, read inputs, RNG, time). Two reference components implemented end-to-end as proof: `constantForce` and `sineMover` (kinematic), with physics tests and inspector UI generated from the schema (Add component menu, enable toggle, remove, reorder).
- [ ] FB-8 — **Protocol v2**: analog inputs (`axes: Record<string, number>` alongside keys), an **events channel** richer than today (`contact` events with impulse/speed/material ids/point; `sensor` enter/exit; `component` events), generic `componentState` readback (per-id Float32/JSON values for gauges/sensors) and a `custom` message type for packages; seeded RNG in the world (`settings.seed`) used by all stochastic features; `SimOp` for `setSeed`, `raycast` queries (request/response by id), `snapshot/restore` (hooks for later time-travel; implement on top of Rapier `takeSnapshot` for rigid bodies with a stub-free no-soft-body fallback documented).
- [ ] FB-9 — **UI registries**: `src/app/registry/` with `commands` (id, label, category, icon, shortcut, enabled(), run()), `tools` (toolbox tools; existing select/joint/measure/blast/projectile re-registered through it), `panels` (tabs in left/right/bottom regions with order + icons), `inspectorSections`, `menus`. The topbar menus, toolbox, left/right panels and shortcut help are all generated from the registries. A **command palette (Ctrl/Cmd+K)** with fuzzy search over commands, scenes, prefabs, settings is included and e2e-tested.
- [ ] FB-10 — **Content registries**: `templates`, `prefabs`, `maps` (new, same shape as templates plus thumbnail/difficulty/tags) are registries that packages append to via a one-line `registerX()` in a `src/model/content/*.ts` file auto-collected with `import.meta.glob`.
- [ ] FB-11 — Settings model extended (`SceneSettings`): `seed`, `substeps`, `environment` (sky preset/time-of-day/fog/exposure — storage only), `bounds` (world bounds + respawn/kill policy — storage only), `units`, `graphics` is *not* per-scene (stays in prefs). Defaults + migration.
- [ ] FB-12 — `docs/ARCHITECTURE.md` rewritten for the new structure (registries, component system, protocol v2, migrations, asset store).
