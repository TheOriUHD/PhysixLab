## Implementation notes

Package TM — all eight items done and verified; one engine limitation recorded (docs/LIMITATIONS.md › Time travel).

* **Where it lives.** Worker: `src/physics/world/{recorder,travel,hash,track}.ts` (+ four one-line hooks in `stepping.ts`, `ops.ts`, `state.ts`, `physicsWorld.ts`), one custom channel `timeline` (`src/physics/timelineChannel.ts`, types in `timelineTypes.ts`) — `protocol.ts` was not touched. Page: `src/app/{timeTravel,ghosts,replayFile,trackMath}.ts`, `src/render/ghostViews.ts`, UI in `src/ui/timeTravel/` registered by the extension `src/ui/extensions/timeTravel.ts` (Timeline, Replay and Ghosts tabs in the bottom dock, `time.*` commands), styles `src/styles/tm.css`.
* **`saveState` / `loadState` was already on `ComponentRuntime`**; what was missing was proof and adoption. `tests/timelineScenes.test.ts` now runs every bundled example scene through seek-and-compare, which found real gaps: the drive network's "already sent to the engine" motor / limit cache (fixed: `saveMotors` / `loadMotors`, called from `ComponentHost`), the hydraulic cylinder's previous-stroke value (fixed). How to adopt the hook is in `docs/EXTENDING.md › How to make a component survive time travel`; the rule for other packages is simply "add an example scene, the test names the culprit".
* **Hot-path cost.** A snapshot costs a few milliseconds, a step a fraction of one, so the interval is chosen to keep snapshots at ~6 % of real time (`Recorder.adapt`), not relative to step cost; memory is capped (default 128 MB, 32–512 in the Replay tab) by thinning, never by dropping the start.
* **Design choices worth knowing.** Rewind is "restore the snapshot at or before the target, re-step with the log" per frame (no per-step pose history); a seek is exact because the input log is applied on the way. Going back and acting starts a new branch (the old future is discarded); the loop region instead *plays through* the recorded past (`Recorder.playThrough`). Recording starts by restoring its own base snapshot into the live world so the live run and its replay share a start (soft bodies are not bit-identical to carrying on).
* **Not done / cheap follow-ups.** The loop wraps at frame granularity (one tick of overshoot) because the page, not the worker, detects the end of the region. `Math.random`-based ids in `model/factory.ts` are fine (ids are data inside the log). A diagnostics panel does not exist yet; when it does it can show `timeTravel.determinismSummary()`.
