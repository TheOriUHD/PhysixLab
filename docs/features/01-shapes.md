## Implementation notes

### Chunk 1 — primitive shapes I (SH-1 .. SH-6)

* **One file per shape** under `src/model/shapes/`, registered after the original eight in `shapes/index.ts` (palette order; the 1–9 keys are unchanged). Shared code: `meshKit.ts` (vertex / triangle collector with **crease-angle normals**, `lathe`, `extrudeOutline` with an ear-clipping triangulator, uvs on everything), `parts.ts` (`boxPart`, `hullPart`, `prismPoints`), `revolve.ts` (convex solids of revolution), `annulus.ts` (ring + tube), `beamSection.ts` (I / L / T), `shapeIcons.ts` (inline SVG icons, so `ui/icons.ts` is untouched). The geometry factories use only the existing `GeometryKit` (`BufferGeometry` + `Float32BufferAttribute`), so no shared type changed.
* **Compound colliders tile the solid, they never overlap**, so the engine's summed mass equals `density × volume()` and `volume()` is an exact closed form of the *collider polyhedron*, not of the smooth ideal. The trick that makes the closed forms exact: consecutive slices of a ring (torus, washer, pipe) have end faces that are mirror images in the slice's bisecting plane, so every side face of the slice's hull is a planar trapezoid and the slice volume is `sin(2π/N) · A · R`; rings of aligned regular N-gons (hemisphere, dome, frustum) are stacks of pyramid frusta, `h/3 (A₁ + A₂ + √(A₁A₂))`. The mesh is built from the *same* polygons, and a unit test integrates each mesh's signed volume and compares it with `volume()` (outward winding and the formula in one check). Consequence: at the defaults a torus (24 × 16) is 3.7 % lighter than the smooth torus `2π²Rr²`; at 64 × 32 it is 0.8 % lighter.
* **Size = bounding box, parameters = ratios.** `halfHeight` is always `size.y / 2`, hole / wall / thickness / flange / web are fractions of a size so the scale gizmo resizes a shape as a whole; `normalizeSize` keeps shapes valid (torus tube ≤ 40 % of the outer diameter so a hole stays open, hemisphere height = radius, dome 5–50 %, arch tall enough for its opening). Meshes are built in a unit frame and shared by `geometryKey` (equal ratio and counts share one geometry whatever the size).
* **The arch's top is one cuboid.** A first version with the deck split into slabs kicked a rolling 0.1 m ball by up to 1.4 cm at the seams (ghost collisions between coplanar convex parts); one deck box rolls like a plain box (`tests/primitiveShapes.test.ts › "a ball rolls the length of the deck …"`).
* **Spiral stairs:** a tread's inner edge is the chord of the column circle pushed out until it is tangent to it, so a tread never overlaps the (exact cylinder) column and nothing is counted twice; its outer edge is a polyline with ≤ 15° per piece. `stepsPerTurn ≥ 6` keeps every tread convex.
* Honest approximations are listed in `docs/LIMITATIONS.md` (“Shapes”).
* e2e: `e2e/tests/shapes1.mjs` adds every shape from the Add tab, checks the inspector rows, edits parameters (undoable), renders a gallery and parameter variants (screenshots `sh1-*.png` looked at), and simulates the torus / arch / stairs / spiral / dynamic bodies in the real worker.
