## Implementation notes — UI-10 / UI-11 / UI-12 (inspector upgrades, calculators, readout)
* Everything new is in `src/ui/inspector/upgrades/*`, `src/ui/readout.ts`, `src/ui/extensions/inspectorUpgrades.ts` and `src/styles/ui-a-inspector.css`. Shared files touched (wrapped in `UI-A` comments): `src/ui/controls.ts` (number fields parse expressions with units, show their value in SI or imperial, expose a scrub handle; vec3 fields get one unit chip; rows record `data-label`), `src/ui/inspector/index.ts` (one call to `enhanceInspector` after the sections are built).
* The inspector toolbar (filter, collapse/expand all, SI / imperial, copy / paste / presets) and the reset buttons are added to the finished DOM by `enhance.ts`, so sections registered by other packages get the filter, label scrubbing and unit switch with no change.
* Unit system, per-field unit overrides and presets live in `localStorage` (`physixlab:ui-a:units`, `physixlab:ui-a:presets`), never in the document; stored data is validated (`sanitizeSnapshot`, `sanitizePresets`) so a corrupt entry falls back to defaults. A field's override is keyed by the label of its row (`length:Position`), so the same row label shares the choice across objects.
* The readout reads only what the engine publishes (pose buffer: position, velocity, spin, net force, kinetic energy; built mass and centre of mass; contact events through `app.contacts`). Potential energy is computed from the scene gravity, `gravityScale` and the centre of mass exactly like the worker's energy statistics. The contact list shows *new* contacts (impact events with impulse and approach speed), not resting ones, because that is what the engine reports per pair.
* Not done / follow-ups: reset-to-default, copy / paste and presets are for bodies only (soft bodies, lights and joints have unit toggles, expressions, scrubbing and the filter but no reset button); the inertia calculator is exact for box / sphere / cylinder and flags every other shape as a bounding-box approximation; the hinge pendulum calculator is a point-mass readout.

* The Charts tab uses the panel registry (`registerPanel`); the dock grows to 300 px while it is the visible tab (CSS `:has`, in charts.css), because 196 px leaves too little plot area. Chart configs persist in `localStorage` (`physixlab.charts.v1`, sanitised on load); recorded data does not.

* Follow-ups: temperature / sensor / component-state signals, per-body contact data and hinge torque need worker-side protocol fields; log axes for the time view; a y-axis zoom.

## Implementation notes — UI-41 / UI-42 (presentation mode, quality of life)
* New code: `src/ui/present/` (pure `model.ts`, `presenter.ts` controller, `panel.ts`), `src/ui/qol/` (DOM-free stores and sniffers + the DOM wiring), `src/ui/extensions/present.ts` and `qol.ts` (commands, menu entries, the Present panel), `src/styles/qol.css`. `installQol(app)` in `main.ts` is the one hook (restores the remembered lens, listens for Esc, records recent scenes, installs the drop target and the paste listener).
* Presentation mode hides everything that is not the viewport or one of its ancestors (walk up from the viewport host, `qol-hidden` class), so panels, docks and floating windows other packages add later are hidden too; toasts are optional. Esc is taken in the capture phase while presenting (it does not also deselect). F10 works while a caption field has focus.
* Capture renders the frame through the full post stack at pixel ratio = scale, copies it to a 2D canvas in the same task (the drawing buffer is not preserved), restores the viewport and encodes a PNG; the scale is reduced (and the toast says so) when the image would exceed the GPU's largest edge or 36 megapixels. "Best quality" switches to the ultra tier for the capture only.
* Lighting presets are the scene's environment presets (VZ-A) written through `store.updateSettings`, so they are saved with the scene and undoable. Depth of field presets write the VZ graphics options (`prefs.graphics.dof`) and the pass focuses on the orbit target. Lens presets set the camera's field of view.
* Recent scenes: `app.emit('sceneLoaded', …)` from `SceneCommands.loadDocument/loadTemplate/loadMap` (a `source` says where it came from); file and paste scenes keep their JSON in a second, budgeted store (4 scenes, 700k characters, 300k per scene); library scenes are reopened by id. Thumbnails: a clean 160×90 JPEG of the viewport (no outline / gizmos), taken once the camera settles and refreshed at most every ~6 s after edits, cached under `physixlab:qol:thumbs:v1` (60 entries, 450k characters); library cards, recent cards and example cards show them.
* Ctrl+V: `edit.paste` no longer prevents the browser's paste event and waits one task; the window `paste` listener claims it only when the clipboard text is a scene and focus is not in a text field (`src/app/pasteClaim.ts`); otherwise entities paste exactly as before.
* Other packages: add an importer with `registerDropHandler('image' | 'mesh' | 'replay' | 'prefabPack', …)` and the overlay and the drop use it; the favourites store is `favouriteStore()`; `getPresenter(app)` is keyed by the scene store because `window.physixlab` is a proxy of the App.
* Not done: nested submenu for Open recent (the menu model has none); thumbnails for example scenes before they are first opened; replays, meshes, images and prefab packs cannot be imported on this branch.
