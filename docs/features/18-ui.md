## Implementation notes — UI-10 / UI-11 / UI-12 (inspector upgrades, calculators, readout)
* Everything new is in `src/ui/inspector/upgrades/*`, `src/ui/readout.ts`, `src/ui/extensions/inspectorUpgrades.ts` and `src/styles/ui-a-inspector.css`. Shared files touched (wrapped in `UI-A` comments): `src/ui/controls.ts` (number fields parse expressions with units, show their value in SI or imperial, expose a scrub handle; vec3 fields get one unit chip; rows record `data-label`), `src/ui/inspector/index.ts` (one call to `enhanceInspector` after the sections are built).
* The inspector toolbar (filter, collapse/expand all, SI / imperial, copy / paste / presets) and the reset buttons are added to the finished DOM by `enhance.ts`, so sections registered by other packages get the filter, label scrubbing and unit switch with no change.
* Unit system, per-field unit overrides and presets live in `localStorage` (`physicslab:ui-a:units`, `physicslab:ui-a:presets`), never in the document; stored data is validated (`sanitizeSnapshot`, `sanitizePresets`) so a corrupt entry falls back to defaults. A field's override is keyed by the label of its row (`length:Position`), so the same row label shares the choice across objects.
* The readout reads only what the engine publishes (pose buffer: position, velocity, spin, net force, kinetic energy; built mass and centre of mass; contact events through `app.contacts`). Potential energy is computed from the scene gravity, `gravityScale` and the centre of mass exactly like the worker's energy statistics. The contact list shows *new* contacts (impact events with impulse and approach speed), not resting ones, because that is what the engine reports per pair.
* Not done / follow-ups: reset-to-default, copy / paste and presets are for bodies only (soft bodies, lights and joints have unit toggles, expressions, scrubbing and the filter but no reset button); the inertia calculator is exact for box / sphere / cylinder and flags every other shape as a bounding-box approximation; the hinge pendulum calculator is a point-mass readout.

## Implementation notes — UI-30 / UI-31 / UI-32 (charts)
* New code is in `src/ui/charts/` (DOM-free cores: `series` ring buffer with decimation, `expr` evaluator, `fft`, `analysis`, `signals`, `model`; DOM: `widget`, `render`, `traceDialog`, `panel`, `appSource`) and `src/styles/charts.css` (imported by `panel.ts`, so `src/main.ts` is untouched). The only shared-file edits are the `chartsPanel` entry in `src/ui/builtin/panels.ts` and the dock tab list assertion in `e2e/tests/registry.mjs`.
* The Charts tab uses the panel registry (`registerPanel`); the dock grows to 300 px while it is the visible tab (CSS `:has`, in charts.css), because 196 px leaves too little plot area. Chart configs persist in `localStorage` (`physicslab.charts.v1`, sanitised on load); recorded data does not.
* Expressions reference bodies by name, id, alias (editable in the trace dialog) or `selected` (follows the selection). Signals are a catalogue (`SIGNALS` in signals.ts; add an entry to add a signal). `contacts` / `contact_force` switch the worker's contact points on while a chart uses them.
* Follow-ups: temperature / sensor / component-state signals, per-body contact data and hinge torque need worker-side protocol fields; log axes for the time view; a y-axis zoom.
