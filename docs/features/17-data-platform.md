# 17 · Data, export, persistence, sharing, API, PWA (package DT)

Depends on: foundation (asset store, migrations), time (replays), visuals (thumbnails), maps/gallery (local gallery UI is MP-50 — DT provides the storage layer).

Honest scope: there is no backend. "Cloud saves/accounts" are provided as **folder sync via the File System Access API** (works with Dropbox/Google Drive/iCloud/OneDrive desktop folders) plus export/import; "multiplayer/collab" is **peer-to-peer WebRTC with copy/paste signalling and BroadcastChannel for same-device tabs**. Document this clearly.

## Implementation notes — DT-1

* **Architecture.** `src/app/export/` is pure TypeScript except two adapters. `scene.ts` turns a `SceneDocument` + a `GeometryProvider` into a neutral node tree (`ExportScene`: nodes with local and world poses, primitives, a deduplicated material table, a list of skipped entities). Writers: `gltf.ts` (JSON + one binary buffer, GLB container, KHR_lights_punctual, LINEAR translation/rotation animation), `obj.ts` (OBJ + MTL, world space), `stl.ts` (binary, optional scale and Z-up), `zip.ts` (stored-entry zip so OBJ and MTL are one download). `threeGeometry.ts` is the provider backed by the shape registry (`shapeGeometry` + `shapeVisualScale`, the same triangles the viewport draws; geometry is shared per spec so repeated shapes share one glTF mesh). `capture.ts` renders PNGs and thumbnails; `download.ts` is the single file-delivery helper (`downloadBlob`; tests set `window.__physicslabCaptureDownloads = true` and read `window.__lastDownload`).
* **Hierarchy.** The document stores members' *world* poses; the glTF node tree nests members under their parent group with local = parent⁻¹ · world, so a viewer shows exactly the same placement. Members whose parent is not part of the export (selection-only) sit at the root.
* **Materials.** MaterialSpec -> pbrMetallicRoughness (sRGB -> linear base colour, opacity -> alpha with BLEND). Ghost bodies and sensor parts are exported translucent as they are drawn. OBJ/MTL gets Kd/Ks/Ns/d approximations.
* **Lazy loading.** `src/ui/extensions/export.ts` registers four commands (`file.export.gltf|obj|stl|png`) and File-menu entries; handlers `import()` the dialog (`src/ui/exportDialog.ts`), which `import()`s `src/app/export/run.ts` on Export. Nothing of the exporters is in the entry chunk.
* **PNG / thumbnails.** Rendered with the viewport's own renderer straight to its canvas (no outline / AO / overlays), resized for the capture and restored in the same task. Up to 2560 px edge the image is rendered at 2x and averaged down (the main renderer has no MSAA); above that it is rendered 1:1. Transparent: sky and ground slab hidden, rendered over black and over white, alpha recovered per pixel by difference matting (exact for translucent materials too; the ground shadow stays). Camera aspect follows the output size (the vertical field of view is kept).
* **Animation.** "Bake animation (s)" samples the poses of the exported bodies ~30x/s from the running simulation for N seconds (starting it if needed, pausing it again afterwards) and writes translation/rotation channels relative to the parent node; bodies that do not move get no channel. It is a real-time capture of what the user would see, not a deterministic replay of the TM recording.
* **Not exported.** Soft bodies (particles; reported in a toast), area lights (no glTF equivalent), paths, joints, render-only skins, texture maps (the document has none on bodies). Imported mesh assets (`meshId`) are exported in place of the shape with their material slots, but the mesh importers (SH) are not on this branch, so that path is only covered by a synthetic asset in tests.
* **Tests.** `tests/export.test.ts`: scene builder (hierarchy, compound parts, selection, mesh asset, every registered shape yields a finite mesh), GLB container/accessor/bufferView consistency, indices in range, POSITION min/max, sRGB->linear, lights, animation accessors, STL size == 84 + 50·n and unit normals, OBJ index ranges and material coverage, and re-imports through three.js's GLTFLoader / OBJLoader / STLLoader (triangle counts, world positions, bounds). `tests/exportZip.test.ts`: zip CRCs/offsets. `e2e/tests/data-export.mjs`: the File menu, PNG 1280x720 and transparent 4K (alpha measured, canvas restored), the thumbnail helper, GLB (container, selection-only), GLB with baked animation, STL and OBJ zip.
* **For other packages.** `import { renderThumbnail, renderThumbnailDataUrl } from 'src/app/export/capture'` (dynamic import recommended); `renderThumbnail(app, 256)` -> `Promise<Blob>` PNG (or `{ mime: 'image/jpeg', quality }`), 256 px on the longer side in the viewport's aspect, editor overlays left out; the visible viewport is not disturbed. Pure builders for headless use: `buildExportScene(doc, provider)` + `buildGlb / buildObj / buildStl`.
