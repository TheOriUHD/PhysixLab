# 17 · Data, export, persistence, sharing, API, PWA (package DT)

Depends on: foundation (asset store, migrations), time (replays), visuals (thumbnails), maps/gallery (local gallery UI is MP-50 — DT provides the storage layer).

Honest scope: there is no backend. "Cloud saves/accounts" are provided as **folder sync via the File System Access API** (works with Dropbox/Google Drive/iCloud/OneDrive desktop folders) plus export/import; "multiplayer/collab" is **peer-to-peer WebRTC with copy/paste signalling and BroadcastChannel for same-device tabs**. Document this clearly.

## Implementation notes

### DT-40 / DT-41 (session DT-B)
* PWA: `public/manifest.webmanifest` (relative paths, file_handlers, share_target), icons generated by `scripts/gen-pwa-icons.mjs` into `public/icons/`, `scripts/vite/pwa.ts` writes `dist/sw.js` from `scripts/vite/sw.template.cjs` with a content-hashed precache of every dist file; registration only when `import.meta.env.PROD` (`src/pwa/`, one call in `src/main.ts`); install command + Help-menu entry in `src/ui/extensions/pwa.ts` (shown only after `beforeinstallprompt`).
* New worker versions wait until the user presses Reload (never mid-edit). Old tabs of a previous version keep working from their network requests until reloaded, but their lazily loaded chunks may 404 after the old cache is deleted: reload them.
* Share target is real: the worker stashes the POSTed file in cache `pl-share` and redirects to `./?shared=1`, which imports it. Browser support for file share targets is limited to Android/ChromeOS/recent Windows.
* Fixed a production-only bug in `scripts/vite/rapierWasm.ts` (DT-42): the pattern left `.buffer` behind, so `fetch(url).buffer` was undefined and the built physics worker failed with "Invalid base URL"; dev server and Vitest were unaffected. The new offline e2e is the first test that runs the production build.
* `scripts/check-size.mjs` skips `sw.js`. Gate: unit 12 new tests, e2e `E2E_FILTER=pwa:` 5/5.
* DT-41: Electron chosen over Tauri (verifiable here); see docs/DESKTOP.md for exactly what was verified.

### DT-23
* **DT-23 (collab):** LWW-register op log (`src/collab/opLog.ts`), store adapter (`docSync.ts`), BroadcastChannel/WebRTC/loopback links (`transport.ts`), host-authoritative `Session`; UI via `src/ui/extensions/collab.ts` (File > Collaborate, `window.physicslabCollab` debug handle). Undo is local (remote batch = one "Remote edit" step). Guests re-simulate the host document (no pose streaming); assets are not synced; no STUN/TURN. See `docs/COLLAB.md`, `docs/LIMITATIONS.md`.
