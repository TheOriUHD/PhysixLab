# 19 · Quality, testing, documentation, release engineering, safety (package QA)

Runs last (and incrementally as other packages land). Goal: confidence and long-term maintainability.

## Testing
- [ ] QA-1 — Physics validation suite expansion: ≥ 25 additional analytic checks (rolling friction, projectile range & max height, orbital period, buoyancy equilibrium, terminal velocity, spring networks, coupled oscillators, torque-free precession, collisions in 2D/3D with restitution, static friction thresholds on curved surfaces, joint reaction forces, gear ratios, pulley systems, energy budgets with dissipation) documented in `docs/VALIDATION.md` with the formula, tolerance and measured error
- [ ] QA-2 — Visual regression: golden screenshots for ≥ 20 key views (scenes, panels, themes, mobile) with a perceptual diff and tolerance, deterministic rendering settings for headless, `npm run test:visual` + `-- --update` flow; baselines committed; CI job
- [ ] QA-3 — Performance regression tests: budgeted benchmarks in CI (physics ms/step for standard scenes, bundle size, frame time smoke in e2e) with tolerances and a trend file
- [ ] QA-4 — Soak tests: long headless runs (e.g. 10 minutes sim time of several scenes) checking no NaN/Infinity, energy bounded, memory stable, no runaway body count; e2e soak (2 minutes wall-clock of UI actions) with no console errors
- [ ] QA-5 — Fuzzing: random scene generators and random edit/undo/redo/op sequences (seeded) against the store, serializer (fuzzed/corrupted JSON must never crash, always sanitised or rejected cleanly), importers (garbage meshes), share-link decoder, and the live-edit sync between document and world (world state equals a fresh build of the document)
- [ ] QA-6 — Coverage report (`npm run coverage`) with thresholds on core packages; test inventory table in docs
